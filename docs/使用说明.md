# 智能衣橱与 AI 穿搭助手使用说明

- 文档版本：2.1.4
- 应用版本：智能衣橱 2.1.4
- 适用系统：Android 8.0（API 26）及以上
- 软件包名：`com.example.wardrobe`

## 1. 软件简介

智能衣橱是一款基于本地衣橱、当前位置、和风天气和通用大模型的 Android
穿搭助手。应用支持拍照录入衣物、分类与搜索、今日 AI 穿搭、单品 AI 搭配、
旅行打包清单、旅行衣橱、搭配库和数据迁移。

衣橱、搭配、图片和 API 配置默认保存在本机。除天气和 AI 请求外，衣橱增删改查、
分类筛选和搜索均可离线使用。

## 2. 安装与升级

### 2.1 首次安装

1. 将 `SmartWardrobe-v2.1.4-release.apk` 发送到 Android 手机。
2. 在文件管理器中点击 APK。
3. 如果系统提示，请允许“安装未知应用”。
4. 安装完成后打开“智能衣橱”。

### 2.2 覆盖升级

正式版沿用包名 `com.example.wardrobe` 和固定 Release 签名。直接从旧正式版
覆盖安装即可，衣橱、搭配、图片和本机配置会保留。

如果系统提示签名冲突，通常是因为旧版本来自其他签名或 Android Studio Debug
包。此类安装无法直接覆盖；需要先备份数据，再决定是否卸载旧包。

Beta 版包名为 `com.example.wardrobe.beta`，可与正式版共存，但两者的数据相互
独立。Beta 仅在衣物详情页额外显示 AI 隐藏描述。

## 3. 首次启动与权限

首次启动时，请选择穿搭偏好：

- 女性
- 男性
- 不限

该偏好会影响 AI 对版型、剪裁、配色和风格的判断，不会隐藏或限制衣橱中的衣物。

应用可能申请以下权限：

- 定位：获取当前位置和当地天气。
- 相机：拍摄衣物照片。
- 相册/图片：选择已有衣物照片。

拒绝定位时会使用默认位置北京。拒绝相机时仍可从相册选图。

## 4. API 配置

点击首页右上角菜单，进入“设置”：

### 4.1 和风天气

填写：

- 和风天气 Host
- 和风天气 Key

Host 和 Key 必须同时填写。天气 Host 示例：

```text
https://your-weather-host/
```

### 4.2 通用大模型

填写：

- LLM Base URL
- LLM API Key
- LLM Model Name

Base URL 示例：

```text
https://api.deepseek.com
```

应用会自动拼接 `/chat/completions`。如果 Base URL 已经包含完整
`/chat/completions` 路径，也可直接填写。

Model Name 必须与服务商文档完全一致，不要包含空格或不可见字符。示例：

```text
deepseek-flash
```

配置只保存在本机 SharedPreferences 中，安装包不包含真实 API Key。

### 4.3 配置缺失提示

- 未配置天气：提示“请先配置天气 API”或“请先在设置中配置 API 信息”。
- 未配置大模型：提示“请配置大模型 Key”。
- 配置不完整时不会发起对应网络请求。

## 5. 首页天气

首页顶部天气卡片显示：

- 当前定位到的省市区或默认位置
- 当天最低温至最高温
- 天气现象
- 天气加载中的圆形进度

在首页内容顶部下拉，可重新定位并强制刷新天气。刷新动画至少展示 1.5 秒。
普通天气请求有 30 分钟缓存，下拉刷新会绕过该缓存。

天气卡片下方会根据天气显示生活提示：

- 雨雪：提醒带伞。
- 高温晴天：提醒防晒或带遮阳伞。
- 大风、雾霾、沙尘：建议佩戴口罩或减少户外活动。
- 天气适宜：显示适合出门。

断网时天气和 AI 请求会被拦截；本地衣橱操作不受影响。

## 6. 今日 AI 穿搭

首页 AI 卡片提供三个模式：

- `✨ 灵感焕新`：优先从全部单品中重新组合。
- `📁 经典套装`：优先复用搭配库中适合今天的套装。
- `✈️ 异地游玩`：生成旅行打包清单或旅行中穿搭。

### 6.1 灵感焕新与经典套装

1. 选择“灵感焕新”或“经典套装”。
2. 在“今天想去哪”中输入面试、约会、郊游等场景。
3. 输入为空时自动使用“日常通勤”。
4. 点击“按场景生成穿搭”，或按键盘回车。
5. 等待 AI 返回 3 套方案；返回少于 3 套时按实际数量显示。
6. 每套方案显示衣物图片、搭配名称、推荐理由和保存按钮。

经典套装模式会优先推荐搭配库中天气合适的套装：

- 复用套装时显示“经典套装推荐”和“经典来源”。
- 套装不适合今天时，AI 会从剩余单品重新组合。
- 搭配库为空时会提示，并回退到灵感组合。

### 6.2 图文匹配与保存

- AI 输出中的衣物名称必须来自本地衣橱。
- 应用优先按完整名称匹配；名称前后有空格时使用兼容匹配。
- 图片缺失或未匹配到衣物时显示默认占位图。
- 点击“保存这套”只保存当前一套方案。
- 保存时弹窗可修改搭配名称。
- 同一方案重复保存会被拦截。

### 6.3 缓存与跨天更新

今日 AI 穿搭按日期、模式、场景和性别偏好缓存。跨天后旧结果自动失效并重新
请求。普通自动生成有 10 秒防抖，避免频繁切换页面导致模型额度消耗。

## 7. 异地游玩与旅行衣橱

### 7.1 生成旅行打包清单

1. 首页选择“✈️ 异地游玩”。
2. 在“想去哪里玩”输入城市、日期和天数，例如：

```text
明天去咸阳玩3天
```

3. 点击“生成旅行清单”。
4. 应用会提取城市、出发日期和旅行天数，并查询目的地未来 7 天天气。
5. AI 返回分类打包清单；衣物卡显示本地衣橱图片和名称。

行程超过 7 天时，天气仍只请求未来 7 天；Prompt 会要求 AI 对超出部分给出
季节性常规建议，不会阻断流程。

### 7.2 加入旅行衣橱

旅行清单衣物卡下方有“加入旅行衣橱”按钮：

- 蓝色按钮表示尚未加入，点击后加入。
- 加入成功后按钮显示“已加入”。
- 再次点击“已加入”可将衣物移出旅行衣橱。
- 操作时按钮会短暂锁定，避免重复写入。

### 7.3 旅行中穿搭

在异地游玩模式下保持输入框为空，点击“生成今日旅行穿搭”：

- 应用只使用已加入旅行衣橱的衣物。
- 旅行衣橱为空时提示“请先添加衣物到旅行衣橱”。
- 结果与首页三套图文方案一致，可逐套保存。

旅行清单和旅行穿搭分别缓存；跨天后失效。

### 7.4 我的衣橱中的旅行页

进入“我的衣橱”顶部可切换：

- 全部衣物
- 旅行衣橱

在“全部衣物”中，已加入旅行衣橱的卡片右上角显示飞机角标。长按卡片可加入
或移出旅行衣橱。

在“旅行衣橱”中只显示已加入的衣物。右下角“清空旅行衣橱”会弹出确认框；
清空只取消旅行标记，不删除主衣橱中的衣物和图片。

## 8. 衣橱管理

### 8.1 添加衣物

1. 进入“我的衣橱”。
2. 点击右下角“添加衣物”。
3. 点击照片区域，在弹窗中选择“拍照”或“从相册选择”。
4. 在裁剪页拖动四角或四边构图，支持双指缩放。
5. 点击“✨ AI 智能识别”可自动填写名称、类别和颜色。
6. 名称和类别为必填项。
7. 可补充颜色/风格和备注。
8. 点击“保存衣物”。

类别包括：

- 上装
- 下装
- 外套
- 裙装
- 鞋履
- 配饰

照片会压缩后保存在应用私有目录，数据库只保存文件名，不保存绝对路径。

AI 视觉识别需要配置支持图片输入的 OpenAI Vision 兼容模型。识别失败时不会
影响手动录入。

### 8.2 分类与搜索

衣橱支持：

- 按类别筛选。
- 按名称模糊搜索。
- 按颜色/风格模糊搜索。

搜索使用 300ms 防抖，停止输入后才执行 SQLite `LIKE` 查询。

### 8.3 详情、编辑与删除

点击衣橱卡片进入“衣物详情”：

- 查看大图、名称、类别、颜色和备注。
- 点击“编辑”修改衣物。
- 点击“删除”并确认；应用会同时删除数据库记录、衣物图片和搭配关联。

Beta 版还会显示数据库中仅供 AI 使用的隐藏衣物描述。

## 9. 单品 AI 搭配

在衣物详情页点击“让 AI 帮我搭这件”：

1. 应用使用已有天气缓存，没有缓存时自动请求天气。
2. 这件衣物作为核心单品，与衣橱其他单品一起发给 AI。
3. 返回多套图文搭配方案。
4. 每套方案可独立保存到搭配库。

未配置大模型、断网或天气不可用时，应用会直接提示。请求期间按钮禁用，
离开页面时未完成请求会被取消。

## 10. 搭配库

进入“搭配库”可查看已保存方案。每张卡片显示：

- 搭配名称
- 来源：今日推荐或单品搭配
- 保存日期
- 天气和温度快照
- 关联衣物图片
- 推荐正文摘要

点击卡片查看完整正文。卡片提供删除按钮，删除前会确认。

搭配与衣物通过 `outfit_items` 关联表保存 ID，因此搭配库可直接展示衣物图片。

## 11. 设置

设置页提供：

- 穿搭偏好：女性、男性、不限
- 和风天气 Host、Key
- LLM Base URL、API Key、Model Name
- 深色模式：跟随系统、浅色模式、深色模式
- 数据迁移：导出数据、导入数据
- 本地数据库状态

点击“保存配置”后配置立即生效。“清空配置”会删除本机天气和大模型配置。

切换浅色/深色模式后，列表、卡片、输入框、文字和按钮均使用 Material 主题色。

## 12. 数据迁移

迁移包用于换机、换模拟器或卸载重装前备份。迁移包包含衣橱、搭配和图片，
不包含 API Key。

### 12.1 导出

1. 设置 → 数据迁移 → 导出数据。
2. 在系统文件选择器中选择保存位置。
3. 成功后会显示衣物、搭配和图片数量。

文件名格式：

```text
SmartWardrobe-backup-YYYYMMDD-HHmmss.zip
```

### 12.2 导入

1. 在新设备安装同一签名的正式版。
2. 设置 → 数据迁移 → 导入数据。
3. 选择 ZIP 文件。
4. 在确认框中点击“确认导入”。
5. 等待校验和恢复完成，应用会自动重新打开。

导入会覆盖当前衣橱、搭配和图片。应用会先校验包格式、SQLite 完整性和表结构；
失败时保留原数据。导入完成后需重新填写 API 配置。

## 13. 本地数据说明

原生 SQLite 数据库文件为 `wardrobe.db`，包含：

- `wardrobe_items`：衣物信息、旅行衣橱标记
- `outfits`：搭配正文、来源、天气和温度
- `outfit_items`：搭配和衣物的多对多关联

其他本地数据：

- SharedPreferences：API 配置、穿搭偏好、主题、场景和 AI 缓存
- 应用私有图片目录：衣物照片
- 天气内存缓存：30 分钟

应用不提供云同步。

## 14. 常见问题

### 14.1 提示未配置天气或大模型

进入首页右上角菜单 → 设置，确认 Host/Key 和 LLM 三项配置均完整，然后保存。

### 14.2 提示网络未连接

检查 Wi-Fi 或移动网络。断网时天气和 AI 请求会被拦截，衣橱本地功能仍可使用。

### 14.3 AI 没有返回内容

可能原因：

- Base URL 不正确
- Model Name 与服务商文档不一致
- API Key 无效
- 余额不足
- 服务端限流
- 请求超时

查看 Snackbar/Toast 提示，并在设置中核对配置。应用日志会记录 HTTP ErrorBody，
包括 429 和服务端错误详情。

### 14.4 AI 推荐无法匹配图片

AI 必须原样返回衣橱中的衣物名称。应用会忽略空白和标点差异进行匹配；完全
未匹配时使用默认占位图，不会崩溃。

### 14.5 天气一直显示默认北京

检查系统是否授予定位权限和定位服务是否开启。定位超时会回退到默认位置。

### 14.6 旅行衣橱为空

先在“异地游玩”的打包结果中点击“加入旅行衣橱”，或在“我的衣橱 → 全部衣物”
中长按衣物加入。

### 14.7 APK 无法覆盖安装

确认旧版本来自同一 Release 签名。Debug 包、Beta 包和正式版包名或签名不同，
不能直接互相覆盖。

### 14.8 换机后如何保留衣橱

旧设备导出 ZIP，新设备安装正式版后导入。API Key 不包含在迁移包中，需要重新配置。

## 15. 注意事项

- 不要公开 `keystore.properties`、签名证书或自己的 API Key。
- 删除应用或清除应用数据会删除本地衣橱、搭配和照片。
- 迁移包含有衣物图片，请妥善保管。
- AI 结果仅作穿搭参考，请结合材质、健康和实际天气判断。

## 16. 演示流程

1. 设置页展示天气和大模型配置。
2. 添加 4 至 6 件不同类别衣物。
3. 首页生成“灵感焕新”三套方案并保存一套。
4. 切换“经典套装”重新生成，展示经典来源。
5. 打开搭配库，展示关联衣物图片和删除入口。
6. 进入衣物详情，演示单品 AI 搭配。
7. 使用“异地游玩”输入城市和天数，生成打包清单。
8. 将清单衣物加入旅行衣橱，再留空输入生成旅行中穿搭。
9. 切换旅行衣橱 Tab，演示飞机角标、长按切换和清空。
10. 切换深色模式并下拉刷新天气。
11. 导出迁移包，再导入同一文件，展示数据恢复。
