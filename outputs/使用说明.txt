智能衣橱 v2.1.4 使用说明

一、安装与升级
1. 将 SmartWardrobe-v2.1.4-release.apk 发送到 Android 手机。
2. 点击 APK 安装，必要时允许“安装未知应用”。
3. 正式版沿用包名 com.example.wardrobe 和固定 Release 签名，
   可直接覆盖旧正式版，衣橱、搭配、图片和本机配置会保留。
4. Beta 包名为 com.example.wardrobe.beta，可与正式版共存，
   但两者数据相互独立。

二、首次启动
1. 选择穿搭偏好：女性、男性或不限。
2. 允许定位、相机和相册权限。
3. 拒绝定位时使用默认位置北京；拒绝相机时仍可从相册选图。

三、API 配置
1. 点击首页右上角三个点，进入“设置”。
2. 填写和风天气 Host 和 Key。
3. 填写 LLM Base URL、API Key 和 Model Name。
4. 点击“保存配置”。

Base URL 示例：https://api.deepseek.com
Model Name 示例：deepseek-flash
应用会自动拼接 /chat/completions。

四、首页天气
天气卡片显示定位地点、最低温至最高温、天气现象和生活提示。
在首页顶部下拉可重新定位并强制刷新天气；刷新动画至少展示 1.5 秒。
普通天气请求有 30 分钟缓存。

五、今日 AI 穿搭
1. 选择“✨ 灵感焕新”或“📁 经典套装”。
2. 在“今天想去哪”输入面试、约会、郊游等场景。
3. 输入为空时自动使用“日常通勤”。
4. 点击“按场景生成穿搭”，或按键盘回车。
5. 等待三套图文方案，返回少于三套时按实际数量显示。
6. 点击“保存这套”可单独保存当前方案。

经典套装模式优先复用搭配库中适合今天天气的套装，不适合时会重新组合单品。
当天结果按日期、模式、场景和性别偏好缓存，跨天后自动失效。

六、异地游玩与旅行衣橱
1. 首页选择“✈️ 异地游玩”。
2. 输入城市、日期和天数，例如：明天去咸阳玩3天。
3. 点击“生成旅行清单”。
4. 清单衣物卡显示图片和名称，可点击“加入旅行衣橱”。
5. 已加入后按钮显示“已加入”，再次点击可移出。
6. 输入框留空并点击“生成今日旅行穿搭”，只使用旅行衣橱中的衣物。

行程超过 7 天时天气仍只取未来 7 天，AI 会对超出部分补充季节性建议。

七、旅行衣橱页
1. 我的衣橱顶部可切换“全部衣物 / 旅行衣橱”。
2. 已加入旅行的衣物在全部衣物中显示飞机角标。
3. 长按衣物卡片可加入或移出旅行衣橱。
4. 旅行衣橱右下角可清空旅行标记；不会删除主衣橱衣物和图片。

八、添加衣物
1. 我的衣橱 → 添加衣物。
2. 点击照片区域，在弹窗中选择“拍照”或“从相册选择”。
3. 在裁剪页拖动四角或四边，支持双指缩放。
4. 可点击“✨ AI 智能识别”自动填写名称、类别和颜色。
5. 填写名称并选择类别：上装、下装、外套、裙装、鞋履、配饰。
6. 可补充颜色/风格和备注。
7. 点击“保存衣物”。

照片压缩后保存到应用私有目录，数据库只保存文件名。

九、衣橱搜索与详情
1. 衣橱支持类别筛选和名称/颜色模糊搜索。
2. 搜索使用 300ms 防抖。
3. 点击衣物进入详情，可编辑或删除。
4. 详情页“让 AI 帮我搭这件”会生成图文方案，每套可单独保存。

十、搭配库
搭配库显示方案名称、来源、日期、天气快照、关联衣物图片和正文摘要。
点击卡片可查看完整内容，卡片支持删除。

十一、设置
设置页支持：
- 穿搭偏好：女性、男性、不限
- 和风天气 Host、Key
- LLM Base URL、Key、Model Name
- 跟随系统、浅色模式、深色模式
- 数据迁移
- 本地数据库状态

十二、数据迁移
1. 旧手机：设置 → 数据迁移 → 导出数据。
2. 新手机：安装正式版后进入设置 → 数据迁移 → 导入数据。
3. 选择 ZIP 并确认导入。
4. 导入会覆盖当前衣橱、搭配和图片。
5. 迁移包不包含 API Key，导入后需重新配置。

十三、常见提示
1. “请先配置天气 API”：到设置填写天气 Host/Key。
2. “请配置大模型 Key”：到设置填写 LLM 三项配置。
3. “网络未连接”：检查 Wi-Fi 或移动网络。
4. “请先添加衣物到旅行衣橱”：先加入打包清单中的衣物或长按衣橱卡片加入。
5. 图片显示占位图：原图可能被删除，可重新编辑衣物并选择照片。
6. “AI 没有返回有效内容”：检查 Base URL、模型名、Key、余额和限流。

十四、注意事项
- 安装包不包含真实 API Key，配置只保存在本机。
- 删除应用或清除应用数据会删除本地衣橱、搭配和照片。
- Debug、Beta 和 Release 的包名或签名不同，不能直接互相覆盖。
- 覆盖正式版前请确认使用同一 Release 签名。
